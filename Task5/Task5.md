# Задание 5. Разработка cutover-плана

## 1. Анализ ситуации и выбор стратегии

**Текущее состояние:**
*   Монолитный подход: файловые базы (Excel), локальные 1С, отсутствие интеграций.
*   Данные децентрализованы и не структурированы (кроме 1С).
*   Целевая архитектура: Микросервисы (Java, K8s, PostgreSQL) + Веб-портал и Мобильное приложение.

**Выбранная стратегия:** **Parallel Run (Параллельный запуск)**

**Обоснование:**
В медицинской сфере критически важна целостность и доступность данных (PHI). Полная остановка клиники для миграции ("Big Bang") несет высокие репутационные и финансовые риски. Стратегия "Branch by abstraction" сложна в реализации, так как исходная система (Excel/файлы) не имеет четкого API для абстрагирования.
**Parallel Run** позволяет запустить новую систему параллельно со старыми процессами (Excel/1С). В течение переходного периода сотрудники будут дублировать ввод данных, что позволит:
1.  Сверить корректность работы новой системы на реальных данных.
2.  Обучить персонал без риска остановки обслуживания пациентов.
3.  Иметь гарантированный план отката (продолжить работу в Excel/1С).

**Ограничения:**
*   Повышенная нагрузка на персонал (двойной ввод данных).
*   Сложность синхронизации (необходимо сверять данные).

## 3. Управление рисками и роли

### Ключевые риски стратегии Parallel Run
1.  **Рассинхронизация данных:**
    *   *Проблема:* Пациент записан в Excel на 10:00, а в Web на 10:15.
    *   *Решение:* Приоритет ("Master") на время миграции имеет старая система (Excel). Все конфликты решаются в пользу Excel до момента Cutover. Введена роль "Data Steward" для ручной сверки.
2.  **Перегрузка персонала:**
    *   *Проблема:* Врачи тратят время приема на заполнение двух форм.
    *   *Решение:* Наем временных администраторов для переноса данных из бумажных карт/Excel в новую систему ("Data Entry Operators").
3.  **Технические сбои новой системы:**
    *   *Проблема:* Web-портал "падает" или тормозит.
    *   *Решение:* Мгновенный откат к работе только в Excel. Данные в новую систему будут внесены позже (асинхронно).

### Распределение ролей
| Роль | Обязанности |
| :--- | :--- |
| **Migration Manager (PM)** | Общая координация, принятие решений Go/No-Go, коммуникация с бизнесом. |
| **System Architect / Tech Lead** | Проектирование плана миграции данных, решение технических проблем интеграции. |
| **DevOps Engineer** | Подготовка K8s, CI/CD, мониторинг, выполнение скриптов переключения. |
| **QA Lead / Data Analyst** | Организация тестирования, сверка данных между системами, контроль качества. |
| **Бизнес-пользователи (Врачи/Ресепшен)** | Дублирование ввода данных, предоставление обратной связи по UX. |
| **Support Team (L1/L2)** | Помощь пользователям на местах, эскалация инцидентов разработчикам. |
