# Задание 3. Оценка Data Encryption at Rest and In Transit

## 1. Классификация данных

Для эффективного выбора методов защиты в системе «Медикаменте» вводится четырехуровневая модель классификации данных по уровню чувствительности и критичности (Risk Profile).

| Уровень (Label) | Описание | Примеры данных | Профиль риска |
| :--- | :--- | :--- | :--- |
| **Public (Публичные)** | Информация, раскрытие которой не несет рисков. | Информация на сайте о клинике, расписание работы (общее), список врачей. | Низкий |
| **Internal (Внутренние)** | Информация для служебного пользования. Утечка не критична, но нежелательна. | Внутренние справочники, неперсонализированная аналитика, технические логи (без PII). | Средний |
| **Confidential (Конфиденциальные)** | Чувствительная информация, требующая защиты по закону (ФЗ-152) или NDA. | **PII (ПДн):** ФИО, телефон, email, паспортные данные, история оплат (PCI DSS scope). Данные сотрудников. | Высокий |
| **Restricted (Строго конфиденциальные)** | Критически важная информация. Утечка наносит непоправимый ущерб. | **PHI (Врачебная тайна):** Медицинские карты, диагнозы, анализы. **Secrets:** Пароли, ключи шифрования, токены доступа. | Критический |

## 2. Стратегия защиты данных

### 2.1 Encryption in Transit (Защита при передаче)
Все данные, передаваемые по сети, должны быть зашифрованы для защиты от перехвата (MITM) и подмены.

*   **Внешний периметр (North-South):**
    *   Все веб-сервисы (Web App, Mobile App API) доступны только по **HTTPS (TLS 1.2/1.3)**.
    *   Использование надежных сертификатов (Let's Encrypt / Commercial CA).
    *   HSTS (HTTP Strict Transport Security) включен.
*   **Внутренний периметр (East-West):**
    *   Взаимодействие между микросервисами в Kubernetes осуществляется через **mTLS** (Mutual TLS). Реализуется через Service Mesh (Istio) или средства фреймворка (Spring Boot SSL).
    *   Шифрование трафика к базам данных (PostgreSQL, ClickHouse) через SSL/TLS.
*   **Удаленный доступ:**
    *   Доступ администраторов через **VPN** (OpenVPN/WireGuard) с MFA.

### 2.2 Encryption at Rest (Защита при хранении)
Данные должны быть защищены на физических носителях на случай кражи дисков или несанкционированного доступа к файловой системе.

*   **Базы данных (PostgreSQL):**
    *   Использование шифрования на уровне файловой системы (LUKS) для томов с данными.
    *   Для полей категории *Restricted* (диагнозы, паспортные данные) — шифрование на уровне приложения (Application-Level Encryption) или колонки (pgcrypto) с хранением ключей в Vault.
*   **Файловое хранилище (S3/MinIO):**
    *   Включение Server-Side Encryption (SSE) по умолчанию.
*   **Аналитическое хранилище (ClickHouse):**
    *   Хранение только обезличенных/псевдонимизированных данных (см. Task 2). Дисковое шифрование.
*   **Резервные копии:**
    *   Обязательное шифрование бэкапов (GPG/AES) перед отправкой в хранилище.
*   **Секреты:**
    *   Запрет на хранение секретов в коде/конфигах. Использование **HashiCorp Vault**.

## 3. Автоматизированный контроль

Для обеспечения непрерывной защиты внедряются следующие средства контроля:

1.  **DLP (Data Loss Prevention):** Мониторинг исходящего трафика на наличие паттернов PII/PHI (номер паспорта, диагнозы) в открытом виде.
2.  **Secret Scanning:** Автоматическое сканирование репозиториев (GitLeaks) на наличие закоммиченных паролей/ключей (Pre-commit hooks + CI/CD pipeline).
3.  **Vulnerability Scanning:** Регулярное сканирование Docker-образов (Trivy) и кода (SonarQube) на уязвимости.
4.  **SIEM & Audit:** Сбор логов доступа к чувствительным данным (ELK Stack). Настройка алертов на аномальное поведение (например, массовая выгрузка карт пациентов).

## 4. Реестр данных и инструментов защиты

| Категория данных | Класс | Необходимость защиты (Обоснование) | Инструменты защиты (In Transit & At Rest) |
| :--- | :--- | :--- | :--- |
| **Персональные данные (PII)**<br>*(ФИО, телефон, email, паспорт)* | Confidential | Требование ФЗ-152. Риск штрафов и репутации. | **Transit:** TLS 1.3 (HTTPS).<br>**Rest:** Шифрование диска (LUKS), маскирование в логах. |
| **Медицинские данные (PHI)**<br>*(Диагнозы, анализы, назначения)* | Restricted | Врачебная тайна. Высокий риск шантажа/ущерба пациенту. | **Transit:** mTLS (внутри K8s), TLS 1.3 (снаружи).<br>**Rest:** Application-Level Encryption (AES-256) для полей БД. Ключи в Vault. |
| **Платежные данные (PCI)**<br>*(История транзакций, токены карт)* | Confidential | Финансовые риски. Соответствие PCI DSS (частично). | **Transit:** TLS 1.2+.<br>**Rest:** Токенизация (хранение токенов вместо PAN), шифрование БД. |
| **Учетные данные (Secrets)**<br>*(Пароли, API keys, сертификаты)* | Restricted | Компрометация ведет к взлому всей системы. | **Transit:** SSH/TLS.<br>**Rest:** Хеширование (bcrypt/Argon2) для паролей. HashiCorp Vault для ключей. |
| **Технические данные**<br>*(Логи, конфиги, метрики)* | Internal | Раскрытие архитектуры упрощает атаки. | **Transit:** TLS для сбора логов.<br>**Rest:** Ограничение прав доступа (RBAC), ротация логов. |
| **Резервные копии (Backups)**<br>*(Дамп всей БД)* | Restricted | Содержат все данные системы в одном месте. | **Transit:** SFTP/TLS.<br>**Rest:** Шифрование архива (GPG/AES) + защита доступа к S3 бакету. |

## 5. Реестр программных и аппаратных средств (Tool Registry)

В рамках стратегии предлагается использовать следующий стек инструментов:

| Инструмент | Категория | Назначение в системе |
| :--- | :--- | :--- |
| **HashiCorp Vault** | Secrets Management | Хранение и ротация ключей шифрования, паролей БД, сертификатов. |
| **Keycloak** | IAM / Auth | Аутентификация (SSO), авторизация (RBAC), управление сессиями. |
| **Cert-Manager (K8s)** | PKI | Автоматический выпуск и обновление TLS сертификатов (Let's Encrypt / Internal). |
| **Istio (Service Mesh)** | Network Security | Обеспечение mTLS между микросервисами, контроль трафика. |
| **ELK Stack (Elastic)** | SIEM / Audit | Сбор и анализ логов безопасности, аудит доступа к данным. |
| **Trivy / GitLeaks** | Security Scanning | Поиск уязвимостей в контейнерах и секретов в коде. |
| **PostgreSQL (pgcrypto)** | DB Security | Модуль для шифрования конкретных столбцов в БД. |
| **LUKS / dm-crypt** | OS Security | Шифрование дисковых разделов на серверах БД и хранилищах. |
